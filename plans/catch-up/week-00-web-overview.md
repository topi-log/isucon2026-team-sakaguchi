## 今週学ぶこと

### ISUCONの基本

- ベンチマーカーがアプリへ多数のリクエストを送り、性能と正しさを評価する
- 速くてもレスポンス内容が不正なら得点にならない
- 改善は「計測 → 仮説 → 変更 → 再計測」で判断する
- 再起動後にも変更が残り、正常に動く必要がある

### HTTPの基本

- URLは接続先と対象リソースを表す
- リクエストにはメソッド、パス、ヘッダー、必要に応じてボディがある
- レスポンスにはステータスコード、ヘッダー、ボディがある
- まず覚えるメソッド: `GET`、`POST`、`PUT`、`DELETE`
- まず覚えるステータス: `200`、`201`、`302`、`400`、`401`、`403`、`404`、`500`
- CookieやAuthorizationヘッダーが認証情報を運ぶ場合がある

### Webシステムの構成

```text
ベンチマーカー / ブラウザ
        ↓ HTTP
      nginx
        ↓
 Node.jsアプリ
        ↓ SQL
      MySQL
```

- nginx: HTTPの受付、アプリへの転送、静的ファイルの配信
- Node.js: 業務ロジック、入力検証、DBアクセス、レスポンス生成
- MySQL: 永続データの保存と検索
- すべてが同じサーバーにあるとは限らない
