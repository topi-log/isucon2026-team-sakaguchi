# 第1週: Linuxとサーバーの基礎

- 期間: 2026年8月17日（月）〜8月23日（日）
- 定例: 8月20日（木）
- ゴール: サーバー上のプロセス、ポート、サービス、ログの対応を調べられる

## 今週学ぶこと

### ファイルと権限

- 絶対パスと相対パス、カレントディレクトリ
- ファイル、ディレクトリ、シンボリックリンク
- 所有者と読み取り・書き込み・実行権限
- 設定は主に`/etc`、ログは主に`/var/log`に置かれるという慣習

### プロセスとサービス

- プログラムは実行されるとプロセスになる
- PIDはプロセスを識別する番号
- systemdのserviceが長時間動くプロセスを管理する
- ポート番号によって、どのプロセスが通信を受け付けるか区別する
- 終了、再起動、異常終了は別の状態である

### リソース

- CPU: 計算処理。使用率が高いこと自体が悪いとは限らない
- メモリ: 実行中のデータやキャッシュを保持する
- ディスクI/O: データの読み書き。待ち時間が発生する
- ネットワーク: サービス間や利用者との通信
- ボトルネックは最も遅い部分が全体を制限する状態

### 標準入出力とログ

- 標準入力、標準出力、標準エラー出力
- ログの時刻、レベル、メッセージを読む
- `less`で検索、`tail -f`で追跡、`journalctl`でserviceのログを読む
- エラーを見つけたら、その直前のログも確認する

## 日別メニュー

### 8/17（月）— 1時間

- `pwd`、`ls -la`、`cd`、`file`、`less`、`find`を使う
- 絶対パスと相対パスで同じファイルを指定する

### 8/18（火）— 1時間

- `ps aux`、`top`、`pgrep`でプロセスを調べる
- PID、CPU使用率、メモリ使用量、実行コマンドを確認する

### 8/19（水）— 1時間

- `ss -lntp`で待受ポートを確認する
- プロセス、ポート、nginx、Node.jsの関係を整理する
- 定例で聞くことをまとめる

### 8/20（木）定例 — 1時間

- 全員の環境構築状況と不明用語を共有する
- 1人が`curl`を実行し、別の人がアクセスログを追う
- 翌週までに使う過去問環境を確定する

### 8/21（金）— 1時間

- `systemctl status`と`journalctl -u`の出力を読む
- start、stop、restart、reloadの違いを確認する
- 実環境のサービスを勝手に停止せず、まずstatusだけを見る

### 8/22（土）— 3時間以上

- 過去問環境を起動する
- nginx、Node.js、MySQLのプロセスとポートを特定する
- nginxの設定ファイルとアクセスログを見つける
- `curl`を1回送り、アクセスログに記録されることを確認する

### 8/23（日）— 3時間以上

- `top`または`htop`でベンチ実行中の変化を見る
- `vmstat 1`でCPUと待ち時間の変化を見る
- 各serviceの起動方法、ログ、設定、ポートを表にする
- 環境を再起動し、再びアクセスできることを確認する

## 最低限使えるようにするコマンド

```bash
pwd
ls -la
less FILE
tail -f FILE
ps aux
top
ss -lntp
systemctl status SERVICE
journalctl -u SERVICE
vmstat 1
```

コマンドを暗記するより、「何を知りたいときに使うか」を説明できることを優先する。
