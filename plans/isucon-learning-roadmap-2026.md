# ISUCON 初参加チーム 学習ロードマップ 2026

## 目標

- 期間: 2026年8月14日（金）〜10月30日（金）
- 本番: 2026年10月31日（土）
- 使用言語: Node.js / TypeScript
- 学習時間の目安: 平日1時間、土日各3時間以上（週11時間以上）
- 毎週木曜日: チーム定例

本番までに、チーム全員が「計測 → ボトルネック特定 → 小さく修正 → 再計測」の流れを守りながら、過去問を役割分担して最後まで走り切れる状態を目指す。

## この計画の学び方

前半4週間（8月14日〜9月13日）は、前提知識のキャッチアップ期間とする。Web、Linux、SQL、Node.jsの基礎がない状態から始めてよい。ただし、知識を網羅してから演習へ進むのではなく、次の順序で学ぶ。

1. 平日に仕組みと用語を理解する
2. 小さなコマンドやコードで挙動を確認する
3. 土日に過去問環境を教材として観察する
4. 分からなかった箇所だけ翌週に補う

前半は「基礎学習70%、実験30%」、9月14日以降は「実践70%、必要な学習30%」を目安にする。序盤のベンチ実行は高得点を狙うためではなく、学んだ構成要素が実際にどう動くかを見るために行う。

### 8月中に説明できるようにする基礎用語

- HTTPリクエストとレスポンス、URL、メソッド、ステータスコード、ヘッダー
- クライアント → nginx → Node.jsアプリ → MySQLという処理の流れ
- プロセス、スレッド、CPU、メモリ、ディスクI/O、ネットワーク
- テーブル、行、主キー、外部キー、インデックス、トランザクション
- 同期・非同期、Promise、`async` / `await`、イベントループ
- レイテンシ、スループット、並行数、ボトルネック、キャッシュ

これらを暗記する必要はない。図または自分の言葉で説明し、実環境のどのログ・プロセス・設定に対応するか分かればよい。

## 最初に決めること

8月20日の定例までに、次を仮決定する。役割は固定せず、9月中は交代して全員が一通り経験する。

- 進行・スコア記録担当: ベンチ実行、ログ、変更管理、残り時間の管理
- アプリ担当: Node.js / TypeScript、プロファイリング、コード改善
- DB・インフラ担当: MySQL、nginx、OSメトリクス、設定変更
- 連絡手段、画面共有方法、作業ブランチ・コミットのルール
- スコア、変更内容、結果、ロールバック方法を残す共有シートまたはMarkdown

3人チームを想定している。人数が異なる場合も、役割そのものは残して兼任する。

## 毎週の基本リズム

| 曜日 | 時間 | 内容 |
|---|---:|---|
| 月 | 1時間 | 前週の結果整理、今週のテーマのインプット |
| 火 | 1時間 | 小さなハンズオン、調査コマンドや改善手法の練習 |

| 金 | 1時間 | 定例の決定を反映、手順書・チートシート更新 |
| 土 | 3時間以上 | 過去問または演習環境でまとまった実践 |

### 準備週: 8/14（金）〜8/16（日）— Webシステムの全体像

到達目標: 一つのリクエストがnginx、Node.js、MySQLを通って返る流れを図にできる。

- 金: ISUCONの概要と、レイテンシ・スループット・正しさが評価される意味を理解する
- 土: HTTPの基礎を学び、ブラウザまたは`curl`でリクエストとレスポンスを観察する
- 日: nginx、Node.js、MySQLの役割を学び、Node.js版過去問の構成図を作る。起動はできる範囲でよい
- 成果物: システム構成図、初めて知った用語一覧、疑問点一覧

### 第1週: 8/17（月）〜8/23（日）— Linuxとサーバーの基礎

木曜定例: 8/20

到達目標: サーバー上で何が動いているかを調べ、ログを読んでリクエストの流れを追える。

- Linuxのディレクトリ、ファイル、権限、プロセス、サービス、ポート、標準入出力を学ぶ
- `pwd`、`ls`、`cd`、`less`、`tail`、`ps`、`top`、`ss`、`systemctl`、`journalctl`を実際に使う
- nginxの設定ファイルとアクセスログを見つけ、1件のリクエストをログまで追う
- CPU、メモリ、ディスクI/O、ネットワークがそれぞれ何を意味するか学ぶ
- 土日: 過去問環境を起動し、プロセス・ポート・ログ・サービスの対応表を作る
- 成果物: Linux基本コマンド集、サービス構成表、環境構築手順

### 第2週: 8/24（月）〜8/30（日）— SQLとインデックス

木曜定例: 8/27

到達目標: SQLの基本操作とテーブル設計を理解し、インデックスの役割を説明できる。

- テーブル、行、型、主キー、外部キー、正規化、トランザクションの基礎を学ぶ
- `SELECT`、`WHERE`、`JOIN`、`GROUP BY`、`ORDER BY`を小さなデータで実行する
- インデックスが「検索を速くする別のデータ構造」であり、書き込みコストも持つことを理解する
- `EXPLAIN`の読み方、全表走査とインデックス走査の違いを学ぶ
- slow query logを有効化し、過去問から重いSQLを1件見つける
- 土日: インデックスを1件追加し、SQL実行時間とベンチ結果の前後を比較する
- 成果物: SQL基礎チートシート、実行計画のBefore/After

### 第3週: 8/31（月）〜9/6（日）— Node.js / TypeScriptと非同期処理の基礎

木曜定例: 9/3

到達目標: Node.jsのリクエスト処理を読み、非同期処理とDBアクセスの流れを説明できる。

- TypeScriptの型、関数、オブジェクト、配列操作、例外処理を復習する
- Promise、`async` / `await`、逐次実行と並行実行、イベントループを小さなコードで確認する
- ルーティング → バリデーション → SQL → レスポンスというコードの流れを過去問で追う
- DBコネクションとコネクションプールの役割を理解する
- 同期API、直列`await`、ループ内SQLが遅くなりやすい理由を学ぶ
- 土日: 1エンドポイントを選び、呼ばれる関数とSQLを図にする。可能なら直列処理を1件だけ計測する
- 成果物: リクエスト処理図、Node.js非同期処理チートシート

### 第4週: 9/7（月）〜9/13（日）— nginx、静的配信、キャッシュ

木曜定例: 9/10

到達目標: ここまでの基礎を接続し、初めて計測ベースの改善を一通り完了する。

- レイテンシ、スループット、並行数、ボトルネックの関係を学ぶ
- nginxアクセスログ、slow query log、`top`などを同じベンチ中に観察する
- 静的ファイル配信とキャッシュの仕組み、正しさを壊す危険を理解する
- 「計測 → 仮説 → 一変更 → 再計測 → 採否」をチームで練習する
- 土日: SQL、静的配信、またはアプリ処理から安全な改善を1件だけ完遂する

## 本番用Runbookに含める項目

### 開始直後

- レギュレーションと当日注意事項を全員で再確認
- 初期状態をコミットし、設定ファイルとサービス構成を把握
- ベンチを変更前に複数回実行し、初期スコアとエラーを記録
- CPU、メモリ、ディスク、ネットワーク、アクセスログ、slow query logを取得
- エンドポイント別の負荷と重いSQLを順位付け

### 改善中

- 担当、仮説、変更、スコア、エラー、採否を常に共有
- 原則として一度に一つの要因を変更
- 改善前後の数値がない変更を残さない
- 大きな変更の前にコミットし、戻せる状態を保つ
- エラー率や整合性を犠牲にしたスコア向上を採用しない

### 終盤

- 終了60分前を目安に新しい大変更を止める
- 全サービス再起動後にベンチが通ることを確認
- 初期化処理、永続化、設定反映、未コミット差分を確認
- 安定した最高スコアの状態へ戻せることを確認
- 提出・終了手順を複数人で読み合わせる

## 習得チェックリスト

### 計測

- [ ] ベンチスコアの揺れを考慮して比較できる
- [ ] CPU、メモリ、I/O、ネットワークのどこが詰まっているか説明できる
- [ ] nginxアクセスログから重いエンドポイントを特定できる
- [ ] slow query logと`EXPLAIN`から重いSQLを特定できる
- [ ] Node.jsのCPU・メモリ・イベントループを観測できる

### 改善

- [ ] 複合インデックスを実行計画に基づいて設計できる
- [ ] N+1やループ内クエリをまとめられる
- [ ] 安全にキャッシュできる条件と無効化条件を説明できる
- [ ] 直列処理、重複計算、不要なI/Oを減らせる
- [ ] nginx、Node.js、MySQLの接続数とタイムアウトを整合させられる

### チーム運用

- [ ] 変更とスコアをリアルタイムに記録できる
- [ ] 競合を避けて変更を統合できる
- [ ] 失敗した変更をすぐに戻せる
- [ ] 全員がベンチ、アプリ、DB・インフラを最低一度担当した
- [ ] 再起動後も安定したスコアを再現できる

## 優先順位

時間が不足した場合は、次の順で守る。

1. 10月の模擬本番2回
2. 計測、SQL、Node.jsの基本
3. 初動・終盤Runbookと再起動確認
4. nginx、キャッシュ、OS・DB設定の個別演習
5. 発展的な再設計

週の途中で遅れた場合、翌週へ全タスクを繰り越さない。成果物と土日の実践を優先し、未消化のインプットは必要になった時点で調べる。
